# Keylo Backend

Backend foundation for Keylo, an AI-powered real-estate lead-response and
site-visit booking assistant. The architecture is a FastAPI modular monolith
with PostgreSQL, SQLAlchemy 2.0, Alembic, and Pydantic v2.

This directory currently implements **Module 0: Backend Foundation**. No
business modules are included.

See the [repository README](../README.md) for the full project overview,
architecture, configuration reference, and security notes.

## Quick start (Windows PowerShell)

```powershell
cd E:\KEYLO\backend

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt

Copy-Item .env.example .env
# Edit .env: use the same strong local password in POSTGRES_PASSWORD and
# DATABASE_URL.

docker compose up -d db
alembic upgrade head

uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Linux/macOS uses `python3 -m venv .venv`, `source .venv/bin/activate`, and
`cp .env.example .env` instead.

## Configuration

Settings are loaded from environment variables and `backend/.env` by
`app/core/config.py`. `DATABASE_URL` and `POSTGRES_PASSWORD` are required;
`.env.example` contains placeholders only.

Production startup validation requires:

- `ENVIRONMENT=production`
- `DEBUG=false`
- a PostgreSQL `DATABASE_URL`
- `CORS_ALLOWED_ORIGINS` explicitly set to one or more non-wildcard origins

The database URL is held in a `SecretStr` and is never logged.

## API endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/` | Basic application information |
| `GET` | `/api/v1/health` | Liveness; process is running |
| `GET` | `/api/v1/health/ready` | Readiness; `SELECT 1` against PostgreSQL |
| `GET` | `/docs` | Swagger UI |

Readiness returns HTTP `503` with `{"status": "not_ready"}` when the database is
unavailable. It does not expose driver errors or connection details.

Errors use the shared envelope:

```json
{
  "success": false,
  "error": {
    "code": "INTERNAL_ERROR",
    "message": "An unexpected error occurred",
    "details": []
  }
}
```

## Alembic

```powershell
alembic upgrade head
alembic current
alembic check
```

`alembic/env.py` imports `app.core.config.get_settings` for the database URL and
`app.db.base.Base` for metadata. There are intentionally no revisions yet. When
adding models, import their modules in `alembic/env.py`, then create and review
an autogenerated migration.

## Tests

```powershell
pytest
```

The test suite forces testing environment variables before importing the app,
uses an in-memory SQLite database with FastAPI dependency overrides, and does
not require PostgreSQL or a developer `.env`.

## Layout

```text
app/
├── main.py                 FastAPI factory, root endpoint, lifespan
├── core/                   Settings, logging, exception handling
├── db/                     Declarative Base, engine, sessions, get_db
└── api/v1/                 Versioned router and health endpoints
alembic/                    Migration environment and versions
tests/                      Unit and integration tests
docker-compose.yml          PostgreSQL 16 with a persistent volume
```

## Limitations

- No authentication or business tables.
- Synchronous database access by design.
- Docker Compose provides PostgreSQL only; the API runs under Uvicorn.
- Tests use SQLite; PostgreSQL connectivity is verified manually.
- No log rotation, metrics, tracing, or rate limiting yet.
